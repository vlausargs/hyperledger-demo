# HLF Helm Charts

Kubernetes Helm charts for the app tier of the Hyperledger Fabric supply-chain stack.

> **The Fabric network itself is provisioned by the hlf-operator, not a Helm chart.**
> See `infra/k8s/operator/` (runbook: `infra/k8s/operator/README.md`) for the CAs,
> orderer, peers, channel, and chaincode. The former `fabric/` skeleton chart was
> retired — it only rendered pods/PVCs with no crypto/MSP/bootstrap wiring, which the
> operator supersedes. These charts cover only `api`, `web`, and `monitoring`.

## Charts

| Chart        | Purpose                                                      |
|--------------|--------------------------------------------------------------|
| `api/`       | Go REST API with HPA (CPU 70 percent, min 2, max 10)         |
| `web/`       | SvelteKit frontend                                           |
| `monitoring/`| Prometheus + Loki + Grafana stack                            |

All images expected to live in `ghcr.io/myindo/*` for a real cluster. On kind, the
`kind-apps` flow builds `hlf-api:local` / `hlf-web:local` and loads them into the node —
see the operator runbook.

## Install (kind — recommended path)

```bash
# Bring up the whole stack (network via operator + apps) from zero:
make kind-all
```

`make kind-apps` alone (re)deploys just `api`/`web` against a running operator network,
generating the api's Fabric connection profile and installing both charts as NodePort
30948 (api) / 30949 (web). See `infra/k8s/operator/scripts/60-apps.sh`.

## Install (real cluster — manual)

```bash
# Lint everything first
helm lint infra/k8s/helm/*/

# API (one release per org)
helm install api-org1 infra/k8s/helm/api \
  --namespace hlf \
  --set env.MSP_ID=Org1MSP \
  --set ingress.hosts[0].host=api-org1.example.com

# Web
helm install web infra/k8s/helm/web \
  --namespace hlf \
  --set ingress.hosts[0].host=app.example.com

# Monitoring
helm install monitoring infra/k8s/helm/monitoring \
  --namespace observability --create-namespace \
  --set ingress.hosts.grafana=grafana.example.com
```

## Notes

- HPA on `api/` targets 70 percent CPU per spec section 8 (50K+ txns/day capacity).
- `ingressClassName` defaults to `nginx`; override for Traefik/Caddy ingress controllers.
- The api's Fabric client identity + connection profile are supplied as Secrets
  (`api-connection` + the operator-issued `org1-admin` identity) mounted into the pod;
  on kind these are generated by `60-apps.sh`. On a real cluster, provision equivalents
  from the operator's issued material.
